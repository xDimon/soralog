# Logger comparison

Generated by `benchmark/compare/run_compare.py`. Times in µs. push: duration of the logging call; resp: from the scheduled moment of the event to the end of the call (open loop only); dlv: from the call to the line being readable from the file; bg CPU: the logger's own threads, % of one core; min–max: throughput range over the repeats. The best value of a column among the loggers with the same number of writers is in bold. See `docs/benchmark/README.md` for the method.

## Logger settings

- **soralog**: Logger -> SinkToFile; event queue of `capacity` events, message limit, write buffer and latency as given; a full queue makes the producer wait.
- **spdlog-async**: async_logger, 1 worker, queue of `capacity` messages, overflow policy `block`; file sink as basic_file_sink_mt (stdio buffer); latency mapped to a periodic flush.
- **spdlog-sync**: synchronous logger: the producer formats and writes under the sink mutex; stdio buffer; latency mapped to a periodic flush.
- **quill**: queue per producer of 128 KiB (compile-time), bounded blocking; the backend thread formats and writes; latency mapped to the minimal flush interval, which is not an upper bound: idle, the backend flushes sooner, under steady load it may flush later; `capacity` and message limit do not apply.
